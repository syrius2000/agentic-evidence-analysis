# three-way-dashboard-reporting Specification

## Purpose
3次元カテゴリカル分析について、非専門家が結論と限界を理解でき、分析者がモデル・数値・設定・文章根拠を追跡できる標準ダッシュボードの振る舞いを定める。

## Requirements

### Requirement: 因子とモデル記号を一貫して表示する
ダッシュボードは、分析変数、因子記号A・B・C、各水準、応答変数を対応づけて表示しなければならない（MUST）。M1〜M9のモデル番号、生成クラス、最大交互作用、日本語の意味は、同じ因子対応を用いなければならない（MUST）。

#### Scenario: UCB Admissionsを表示する
- **WHEN** A=Dept、B=Gender、C=Admitの設定でダッシュボードを生成する
- **THEN** 因子凡例と全モデル説明で同じ対応を使用し、M5をDeptで条件付けたGenderとAdmitの条件付き独立として表示する

### Requirement: ポアソン明示式BICで候補モデルを比較する
ダッシュボードは、ポアソン完全対数尤度、切片を含むパラメータ数p、総度数Nによる `-2 log L + p log N` をBICの主表示としなければならない（MUST）。比較可能な9モデルをBIC昇順で初期表示し、モデル名、生成クラス、残差自由度、逸脱度、BIC、ΔBICで並べ替え可能にしなければならない（MUST）。

#### Scenario: UCBの最良モデルを表示する
- **WHEN** UCB固定入力の9モデルが正常に推定される
- **THEN** M5をBIC最小、M8を次点として示し、M5のBICを332.3119、M8のBICを339.1982の許容誤差内で表示する

#### Scenario: 候補モデルが評価不能である
- **WHEN** 候補モデルが識別不能、収束不良、または比較不能である
- **THEN** 理由と評価状態を表示し、そのモデルを通常のBIC順位または最良モデル判定へ混ぜない

### Requirement: 相対的なモデル選択として説明する
ダッシュボードは、BIC最小モデルの番号、日本語の意味、比較候補数、次点との差、推定状態を早い段階で提示しなければならない（MUST）。その表示は候補集合内の相対評価であり、モデルが真であること、因果関係、差や関連の不存在を証明しないと説明しなければならない（MUST）。

#### Scenario: M5を要約する
- **WHEN** M5のBICが9候補中で最小である
- **THEN** 「Deptで層別するとGenderとAdmitは条件付き独立」というモデル上の意味と、真の独立や公平性の証明ではない限界を併記する

### Requirement: エグゼクティブサマリーの根拠を検証する
本番ダッシュボードは、平易な要約、統計的根拠、解釈上の限界と次の確認の3層で日本語考察を表示しなければならない（MUST）。考察が参照する結果JSONのSHA-256、JSON Pointer、数値が一致する場合だけ統合しなければならない（MUST）。

#### Scenario: 考察の数値が改変されている
- **WHEN** 考察の結果ハッシュ、JSON Pointer、または登録数値が計算結果と一致しない
- **THEN** 本番HTML生成を失敗させ、不一致の考察を完成レポートとして表示しない

### Requirement: NEJM/Nature Medical調の学術標準デザインと用語集アコーディオンを提供する
ダッシュボードは、NEJM / Nature Medical 調の臨床・学術標準テーマ（カード背景 `#F6F8FB`、枠線 1px `#E2E8F0`、シャドウ排除、学術ネイビー `#1F4D7A`、バーガンディ `#9B2945`）を採用し、因子群の一貫したカラーパレットと統計状態発散色（正残差 `#0F766E` / 負残差 `#B45309` / 隔離セル琥珀色 `#A16207`）を分離して表示しなければならない（MUST）。
また、末尾に 3次元対数線形モデル（M1〜M9）、明示式 BIC、Rao スコア、多項 Dirichlet 事後推論、および学術リファレンスを網羅したネイティブアコーディオン（`<details class="glossary-accordion">`）を設置しなければならない（MUST）。アコーディオン内の HTML は、Pandoc の Markdown インデント誤認（`pre > code` 化）を排除するため、Pandoc Raw HTML Block（` ```{=html} `）を用いてレンダリングしなければならない（MUST）。

#### Scenario: 3次元ダッシュボードを学術テーマで描画する
- **WHEN** 3次元集計表からダッシュボード HTML をレンダリングする
- **THEN** 全カードが細枠線と学術ネイビーアクセントで描画され、因子水準間で一貫したカラーパレットが維持される

#### Scenario: 用語集アコーディオンを開閉する
- **WHEN** 生成された HTML の末尾にある用語集アコーディオンをクリックする
- **THEN** JavaScript 非依存のネイティブ `<details>` としてスムーズに開閉し、内部テキストが `<pre><code>` にエスケープされず整形表示される

### Requirement: 単一HTMLを完全オフラインで利用できる
ダッシュボードは単一HTMLとして生成され、インターネット接続なしで数式、表、タブ、折りたたみ、列ソート、埋め込み図を利用できなければならない（MUST）。閲覧時に外部script、stylesheet、Ajax、フォント資産を取得してはならない（MUST）。対象表示幅はデスクトップとする。静的スキャンにおいて外部通信（`http:`, `https:`, `//`）および OS ローカル絶対パス（`/Users/`, `/home/` 等）の参照数が 0 件でなければならない（MUST）。

#### Scenario: ネットワークを遮断して開く
- **WHEN** 完成HTMLをネットワーク遮断状態のデスクトップブラウザで開く
- **THEN** 数式と全主要セクションが表示され、モデル表のソートとタブ・折りたたみ操作が動作する

#### Scenario: 外部アセットおよびローカルパスの静的スキャンを行う
- **WHEN** 生成された HTML に対して静的正規表現スキャンを実行する
- **THEN** 外部 CDN、Web フォント、外部プロトコル、および OS ローカル絶対パスの参照が 0 件として検出される

### Requirement: 標準参照版の来歴を追跡できる
旧AG UI参照版とUCB新標準版は、入力識別、ソースリビジョン、生成条件、実使用依存版、成果物SHA-256を持つmanifestとともに保存しなければならない（MUST）。参照版にローカル絶対パス、機微情報、不要な生成ログを含めてはならない（MUST）。

#### Scenario: UCB標準版を再生成する
- **WHEN** manifestの入力と生成条件を使用して標準版を再生成する
- **THEN** 数値契約と主要UI契約が固定参照に一致し、環境差による成果物差を識別できる
