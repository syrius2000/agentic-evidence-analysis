## 背景

目的と対象範囲は[proposal](proposal.md)、必須の振る舞いは[モデル評価](specs/three-way-model-assessment/spec.md)、[セル解釈](specs/cell-evidence-interpretation/spec.md)、[受入検証](specs/three-way-validation-cases/spec.md)を正本とする。

現行エンジンは主効果対飽和のPoisson GLMと残差由来Scoreを使用する。RのBIC呼出しと総度数を渡すEBICでは標本サイズの定義を別途確認する必要がある。既存Pass 0の出力だけでは、度数・欠測・セル構造の判断材料が不足する。本設計は、この本番処理を置き換えず、独立した検証プログラムで採否を判断する。

## 設計上の到達点と対象外

到達点は、計算方式を変更しても照合に使える参照値、定義が追跡可能な結果JSON、候補方式の採否記録を作ることである。数値検証と、後続のAI・レポート受入を分ける。

本番スキル、共有schema、既存の出力JSON、元CSVの変更はこの試作に含めない。追加のMCMC基盤、依存関係の導入、階層ベイズの本格実装は行わず、必要性を採否記録に残す。現行Scoreの正当化や特定手法の採用を、試作開始時の結論にしない。

## 設計判断

### 1. 小さな独立検証プログラムに分離する

実行指示後の変更候補を以下に限定する。各ファイルは検証の役割を持ち、本番エントリーポイントから呼ばない。

| 配置 | 役割 |
| --- | --- |
| tests/statistical_foundations/prepare_cases.R | 入力の検分補足、3元集約、派生表と人工表の生成 |
| tests/statistical_foundations/validate_config.R | 試作用設定・度数・水準・抽出条件の検証 |
| tests/statistical_foundations/fit_models.R | 候補モデル、セル診断、ベイズ校正計算 |
| tests/statistical_foundations/reference_values.R | 閉形式と反復比例適合による独立参照計算 |
| tests/statistical_foundations/check_results.R | 参照値照合とケースごとの状態出力 |
| tests/statistical_foundations/run_validation.R | --configを受ける単一の実行入口 |
| tests/fixtures/statistical_foundations/case_manifest.json | 入力定義、モデル、許容誤差、来歴、シナリオ対応 |
| tests/fixtures/statistical_foundations/analysis_config.schema.json | 試作用の入力契約。本番schemaと区別する |

実行結果は output/statistical_foundations/run_<run_id先頭16文字>/ に隔離し、既存の実行先が存在すれば上書きせず別run IDを要求する。設定・検分・派生CSV・環境情報・参照値・照合結果を保存する。管理用の日本語検証報告は docs/Artifacts/statistical_validation_NNN_MMDD.md に保存し、生成結果の識別情報と再現手順を記載する。結果本体がGit管理外である点を引継ぎに明記する。

Rのbase・stats・utilsを計算の中心とし、既存のjsonliteをJSON入出力に使用する。既存inspect_data.Rに必要なdplyr・readrも事前確認する。不足パッケージを解析中に自動インストールしない。ライブラリの版は実行時に記録する。

代替の本番コードへの直接追加は、検証対象と正解の実装が混ざるため採用しない。

### 2. Pass 0と試作用設定を具体化する

最初に既存inspect_data.Rを入力ごとに実行し、その後prepare_cases.Rで度数・欠測・セル網羅性を補足する。これは記述的な入力検分であり、モデル適合は設定合意後とする。

analysis_config.jsonは本番と同じ input・vars・freq・output_dir・run_id を持ち、試作専用のschema_version、response_var、sampling、levels、missing_policy、absent_cell_policy、structural_zeros、filters、model_ids、prior、reference_tolerance、seedを追加する。実装前にcase_manifestと試作schemaで値域を固定し、未知キーは拒否する。本番設定として誤用しないようschema識別子を分ける。

samplingには標本単位・総度数の意味・独立性に関する利用者の申告と限界を記録する。集計表だけから患者の重複やクラスタ依存を自動判定できるとは扱わない。人工100倍化は生成時の来歴で識別する。

欠測・未記載セルの意味が未確定なら推論を保留する。初回試作は完全なセル定義と標本ゼロに対応し、構造ゼロのある推論は理由付き保留とする。構造ゼロ対応の本格モデルは今回の方式選定結果を受けた別範囲とする。

抽出は初回試作では列名・等値・集合包含からなる構造化条件だけを受け付け、任意のR式を評価しない。条件なしを明示し、未知列・未知演算子は拒否する。これは既存subset_exprの修正ではない。

### 3. 3元表の候補モデルを9個に固定する

変数をA・B・Cとし、主効果を必ず含む階層的対数線形モデルを用いる。以下の角括弧はモデルに含める最大交互作用を表す。

| 種類 | 候補 | 問う構造 |
| --- | --- | --- |
| 相互独立 | [A][B][C] | 全変数が独立 |
| 1組だけの関連 | [AB][C]、[AC][B]、[BC][A] | 特定の2変数間の関連 |
| 条件付き独立 | [AB][AC]、[AB][BC]、[AC][BC] | 第3変数で条件付けた独立性 |
| 均一連関 | [AB][AC][BC] | 全2因子関連を許し3次交互作用を含まない |
| 飽和 | [ABC] | 3次交互作用まで含む |

目的変数未指定でも同じ候補を評価し、指定時は説明と効果量の切り口を変える。モデル集合を目的変数の有無で黙って変えない。

Poisson GLMを主計算とし、同じ周辺制約を与えたstats::loglinの反復比例適合を照合に用いる。正の期待度数を持つ正則な表を主照合ケースとする。飽和モデルやゼロセルで有限の係数が得られない場合は、境界上の適合と正則な推定を区別し、通常の近似BF・検定の順位に混ぜない。

各モデルの適合値・対数尤度・階数・逸脱度を保存する。入れ子モデルの差は自由度差と比較方向を明示する。P値は適用条件の確認後に補助表示し、自動的な一律の勝者判定には使わない。

代替の独立対飽和だけの比較は、条件付き関連を説明できないため主設計にしない。無制限の変数・モデル探索も今回の3次元支援には含めない。

### 4. 標本サイズとモデル比較を分離して検証する

初回の参照設計は、固定した水準数の多項標本として総度数Nを標本サイズとする。Poisson表現の総数に関する項は比較するモデル間で共通であることを導出・照合する。多項パラメータ数とPoissonの切片を含む階数の差も記録し、絶対BIC値の違いとモデル間差の一致を区別する。

BIC相当量は明示した尤度・自由パラメータ数・log(N)から再構成し、stats::BICが返す値は実装監査の比較列とする。集計セル数をNとして使う計算を無条件に正解としない。

EBICは現行式と根拠文献のモデル空間・組合せ罰則の対応を監査する。9個の候補だけの探索で追加罰則が必要か、どの事前分布・モデル空間に対応するかを採否記録で結論付ける。根拠が確認できなければ近似BFとして採用せず、診断用の旧方式に留める。

モデル間の近似log BFは比較方向と近似であることを付ける。BFへの指数変換は表示可能な範囲だけ行い、主保存値をlog BFとする。BFはモデルの事後確率と異なり、事後モデル確率には別途モデル事前確率が必要である。

### 5. セルScoreを実際の局所モデル比較と照合する

各セルについて、現行のPearson残差二乗とk log(N)を用いる値を旧方式として再現する。それとは別に、固定した基準モデルに1セルのダミーを追加したモデルを適合し、再推定による尤度差・階数差を求める。

相互独立を主照合の基準、均一連関を追加の基準とする。ダミーが既存列に従属する場合や境界推定になる場合は保留する。残差二乗と2倍の対数尤度差が一般に一致するとは仮定しない。採否記録では近似誤差と成立条件を示し、正当化できない呼称を引き継がない。

セル診断の主表示候補は観測・期待度数、観測/期待比、符号付き残差、適用可能な割合差である。基準モデルと分母を常に付ける。全セルを評価した数と上位抽出の規則を保存する。

初回試作のセル順位は探索的であり、FDR/FWER制御を保証しない。局所の比較値や区間を全セル同時の確証的判定に使わない。確証的なセル選択が必要なら多重性制御の検証を追加する別の範囲とする。

### 6. 明示的なベイズ計算を小さく校正する

本格的な階層モデルの前に、全セルの確率pにDirichlet事前分布を置く多項モデルを、事後推定と感度確認の校正ケースにする。これは対数線形モデル全体のベイズ推定や階層モデルの代替ではない。

セル数Kに対して事前パラメータをa/Kとし、総集中度aは1を主設定、0.1と10を感度設定とする。これらは比較試作の設定であり、汎用の推奨事前分布とは呼ばない。事後はDirichlet(y+a/K)であり、セル確率の平均と95%等裾区間を解析式・ベータ周辺分布で求める。条件付き割合は該当セル集合で正規化した分布として扱う。

事後乱数は基準seed=20260906で20,000回生成し、解析的平均・区間と照合する。セル間・層間の割合差等は同一の同時事後標本から求め、独立なセル確率と仮定しない。点ごとの区間は同時区間ではないと明示する。

多項の事後予測で総度数を固定した表を生成し、事前に選んだ不一致指標の予測分布を確認する。飽和Dirichletモデルでの確認は情報が弱いことを記録し、構造モデルの適合保証に転用しない。独立な事後標本にMCMCの収束診断を形式的に課すことはせず、解析値との一致とMonte Carlo誤差を検証する。

加えて、相互独立モデルの各変数周辺にDirichlet事前分布を置き、飽和モデルとの周辺尤度比を対数ベータ関数で解析計算する。同じセル観測の多項係数は両モデルに共通として扱う。各周辺の総集中度をaに合わせた設定とモデル事前を明記し、得たBFはこの事前指定に依存する校正値とする。他の条件付き独立・均一連関モデルまで厳密BFを算出したと主張しない。

階層的な縮約方式は、必要な事前設計・計算基盤・期待する改善・説明負担をこの結果と比較して採用候補か後続課題かを判断する。新しいMCMC依存の追加までを未決事項として暗黙に実装者へ委ねない。

### 7. 受入ケースと誤差基準を先に固定する

主ケースはTitanicの16セル・N=2,201と、同じ構成比のN=220,100とする。目的変数なし・Survived指定について両倍率を同じプログラムで実行する。これは既存スキルのエンドツーエンド受入の代替ではなく、後段で同じ入力を再利用する統計基盤検証である。

人工表はA・B・Cを各2水準として以下の3個を使う。生成前に式・水準順と期待する制約をcase_manifestに固定する。

- 独立: 各セル度数をu_i v_j w_kとし、u=(1,2)、v=(2,3)、w=(3,4)。
- ABのみ関連: AB行列を((30,10),(10,30))、Cの倍率を(1,2)とし、ABの各セルにその倍率を掛ける。
- 層で関連が異なる: Cの第1層は((40,10),(10,40))、第2層は((10,40),(40,10))。全体と層別の違いを確認する。

独立モデルの期待値は1変数周辺の積/N²、例えばAとBがCの下で独立のモデルは n_i+k n_+jk/n_++k を閉形式の参照にする。均一連関には独立の反復比例適合を使う。飽和の期待値は観測値とする。主計算の内部関数を参照計算側で呼ばない。

決定的な照合の暫定実行基準は、度数・セル数の一致は厳密、浮動小数値は |x-r| <= 1e-8 + 1e-6|r| とする。log BFなど大きな差し引きを伴う量は対数尺度で照合する。確率的な平均は独立標本から見積もるMCSEの5倍と上記数値許容差を用い、区間端点は解析分布での累積確率との差が5 sqrt(q(1-q)/S)+1e-4以内か確認する。

これらの閾値は結果を見る前にmanifestへ固定する。妥当な理由で変更が必要なら不合格の記録を保持し、理由・改訂版・再実行を記録する。数値の一致は数理的妥当性そのものの証明ではないため、導出と適用条件の検証を別に残す。

### 8. 後段へ渡すJSONと採否記録

試作の出力は以下の単位とし、本番のevidence_results.jsonへそのまま混在させない。

| 単位 | 主な情報 |
| --- | --- |
| provenance | 入力ハッシュ、設定、変換、環境、乱数条件、人工倍率 |
| input_summary | 行数、セル数、総度数、水準、欠測・ゼロの扱い |
| models | 識別子、モデル構造、尤度、階数、N、罰則、適用状態 |
| comparisons | モデルの組、方向、指標、近似か厳密か、保留理由 |
| cells | 水準、観測・期待値、基準モデル、方向、指標、分母 |
| posterior | 事前、推定対象、点推定、区間、感度、適合・精度確認 |
| checks | ケース・仕様シナリオ・参照値・差・閾値・判定 |
| decisions | 各方式の採否、根拠、適用範囲、互換性、未検証事項 |

計算不能はJSONのnullと状態・理由で表し、NaNやInfを通常値として保存しない。計算状態と検証状態を分ける。後段のAIはこれらへの参照を持つ主張を作り、観測結果・仮説・限界・次の分析を分離する。

3つのspecの各シナリオについて、試作の実行検証・採否文書の確認・後段実LLM評価のどこで判定するかを一覧化する。未実施を合格で埋めない。

## リスクと対応

- 小さい表のBIC近似や境界MLEの不適切な使用 → 厳密BFの小ケース校正と推定状態を併記し、近似成立を確認できない比較を保留する。
- 集計データでは反復観測や交絡を確認できない → Pass 0の申告と適用限界を保存し、関連から因果を断定しない。
- 経験的な残差順位を新しい確率指標と誤読する → 指標の名称、数式、基準モデル、保証範囲を分離する。
- ゼロセルを事前分布で滑らかにすれば構造ゼロも解決すると誤解する → 構造ゼロはこの試作の推論対象外として保留する。
- 同じコードによる自己照合 → 閉形式・反復比例適合・解析的事後分布を独立参照として使う。
- 100倍化を性能検証と誤解する → セル数は同じであり、標本サイズ感度の検証と明記する。大量行・高水準数の性能保証は別課題とする。
- 検証設計の拡大 → 9モデル、Titanic、3人工表、最小異常系に固定し、階層MCMC・本番統合を別段階へ渡す。
