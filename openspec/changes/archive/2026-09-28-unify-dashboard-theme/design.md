## 現状と制約

動機は [提案書](proposal.md)を参照。既存の共通 CSS は `.agents/shared/dashboard_theme.css` にあり、2次元・3次元 Dashboard が読み込む。categorical の `THEME_TOKENS` と `get_row_palette` はテンプレート内にあり、reporting は R 文字列内に独自 CSS と `practical_bg` 写像を持つ。questionnaire の2つの Rmd は `flatly` を指定し、Dashboard には独自のグラデーションがある。表示上の要件は [差分仕様](specs/shared-dashboard-presentation/spec.md)を参照する。

## 目標と対象外

**目標**

- 共通 CSS と共有 R トークンの値を唯一の色正本として、対象4スキルの HTML に反映する。
- ページクロムと意味付き着色を区別し、比較表の列・セル境界を維持する。
- 生成 HTML はインライン CSS を保持し、外部資産に依存しない。

**対象外**

- 統計値の計算、`summary_df` の40フィールド、比較表12列、判定ルールの変更。
- 新しい CSS カスタムプロパティ層、追加パッケージ、HTML 未実装スキルのレンダラー作成。

## 技術上の決定

### 1. 色正本は共有 CSS と共有 R トークンに置く

categorical 内の `THEME_TOKENS` と決定論的な行パレット関数を `.agents/shared/dashboard_theme_tokens.R` へ抽出する。CSS と R の対応色は値を完全一致させる。Rmd の局所定義を取り除き、共通資産の解決時にトークンファイル欠落を明示的に検出する。CSS `--*` 変数層を追加する案は、計画書で除外されたため採らない。

### 2. 共有 CSS を HTML 内に埋め込み、局所 CSS は構造に限定する

既存の2次元・3次元と同じ方式で reporting と questionnaire のレンダラーが共有 CSS を読み込み、生成 HTML の `<style>` に入れる。局所 CSS はレイアウト、操作、統計状態の限定的な表示に使い、`body`、見出し、背景、主アクセントを上書きしない。reporting の R 文字列内 CSS は共有 CSS の後に配置する場合でも競合宣言を取り除く。`flatly` を questionnaire の2テンプレートから外す。Bootstrap の既定余白に依存していた箇所は既存コンテナへ局所的に補う。CSS ファイルへの外部リンク案は自己完結契約に反するため採らない。

### 3. 意味付き着色は現行の分岐を保ち、色値のみ写像する

reporting の `practical_bg` は T を `#9B2945`、N を `#1F4D7A`、R を `#64748B` と同系、U3 を低 α のスレート系へ写像する。既存の強度・分岐・適用セルは保持し、RD・方向支持・精度などへ背景色を広げない。CTA と表頭はネイビーへ移す。計算・`summary_df` からの指標搬送に手を加えず、表示時の再判定も追加しない。旧色を残して CSS で覆う案は、禁止色が生成物に残るため採らない。

### 4. 検証は静的契約と再生成 HTML の両方で行う

静的チェックでは4スキルの共有資産参照、禁止アクセント、`flatly` 残留、reporting の実務領域セル限定を確認する。検索範囲は製品テンプレートとレンダラーに限定し、説明文書・旧 QA・fixture の履歴を対象外とする。代表 fixture を再レンダリングしてインライン CSS、DOM 構造、12列、オフライン性を確認し、更新した fixture HTML をレビュー可能な差分にする。既存 HTML のコピーによる代替は認めない。

## リスクと対策

- `flatly` 除去で questionnaire の余白・文字サイズが変わる → 代表 HTML を目視確認し、共有 CSS と既存コンテナの範囲で補正する。
- 低 α の色で実務領域セルの視認性が下がる → T/N/R/U3 の各 fixture セルを確認して不透明度を調整する。
- CSS の読み込み順で旧スタイルが勝つ → 生成 HTML 内の実効セレクタを確認し、競合する局所宣言を除去する。
- 共有資産の解決に失敗する → 既存の root 解決と欠落時の明示エラーを踏襲する。

## 適用と復元

適用は共有 R トークン、テンプレート、reporting、questionnaire、文書・検証の順に進める。回帰が出た場合は当該作業ブランチ上の変更単位で復元し、主ブランチへの集約は別判断とする。
