## Why

対数線形モデル比較において、モデル名として英語の内部識別子（`cond_indep_BC_given_A` 等）がそのまま出力されており、因子記号（$A, B, C$）と実変数（学科、性別、合否等）の対応や数学的定義（ブラケット表記 $[AB][AC]$、条件付き独立記号 $(B \perp\!\!\!\perp C \mid A)$、ポアソン対数線形モデル式）が欠落している。これにより、読者にモデルの意味が伝わりにくく主観的な印象を与える懸念があり、また候補モデルが「仮定する構造」とBIC最小による「相対的採択」の区別が曖昧になりやすいため、早期段階での数学的注記の常設と客観的提示への厳密化が必要である。

## What Changes

- **因子記号と実変数の明示的マッピング**: 分析変数（`vars`）の順序に基づく因子記号（$A, B, C$）と実変数名の対応関係を Pass 0 から一貫して定義し、結果メタデータ（`models.factor_map`）およびダッシュボード上に常時明記する。
- **モデル仕様への数学的メタデータの追加**: 3元表の9候補モデル（M1〜M9）に対し、生成クラス（`generators`）を正本として定義し、ブラケット記法（$[AB][AC]$）、実変数展開記法（例: $[\mathrm{Dept},\mathrm{Gender}][\mathrm{Dept},\mathrm{Admit}]$）、構造化された条件付き独立情報（例: $(B \perp\!\!\!\perp C \mid A)$）、および日本語の構造解説を導出可能にする。
- **結果 JSON (`evidence_results.json`) の分離・構造化**: `models` 配下に `factor_map`（変数対応）および `definitions`（各モデルの数理辞書: 生成クラス、独立性構造、ブラケット・LaTeX表記、実適合式、日本語解説）を新設する。数値比較表である `models.summary` は軽量な既存構造を維持し、ダッシュボード表示時に必要なメタデータを参照・最小限結合する設計とする。
- **ダッシュボード (`dashboard.Rmd`) の数学的注記強化と3段構成レイアウト**: 
  1. ページ最上部（主要指標カードより前）に「変数定義・因子記号凡例」を常時表示し、有効な数理定義が存在する場合は主要指標カードでもBIC最小モデルの構造仮定を明記する（定義未収録または不整合時はその状態を表示し推測補完しない）。
  2. モデル比較表の直前に記法の読み方（ブラケット記法）とBIC算式・解釈注釈を配置する。
  3. モデル比較DT表は「モデルと仮定（短い構造説明・詳細リンク）」「生成クラス（等幅テキストブラケット）」「残差自由度」「逸脱度」「BIC」「ΔBIC」のクリーンな6列構成とし、表直下に当該次元の候補モデル（3元表は9候補、2元表は2候補）の数理詳細アコーディオン（`<details>`、有効な `best_model_id` が存在する場合のみ初期展開）を配置する。定義の存在と適合結果の有無を区別し、`best_model_id` が欠落または不正な場合は先頭候補などを勝手に初期展開しない。これにより、DT再描画への数式組版依存を低減し、表の視認性と静的数式の表示安定性を両立する。
- **仮定と実証の厳格な峻別**: AI 考察（Pass 2）およびレポート記述において、「モデルが仮定する条件付き独立性」と「BICによる候補間の相対評価」を峻別し、モデル選択のみを根拠に差別の不存在や完全独立を断定しない記述基準を徹底する。

### 数学的定義と生成元の一貫性

- `analysis_config.json` の `vars` を変数順序の正本とし、記号対応（`factor_map`: $A, B, C$）はそこから導出する。対応表を別途手入力させず、`response_var` の指定で順序を暗黙に変更しない。
- モデル仕様辞書（Rのリスト）の正本は「生成クラス（`generators`）」を構造化して持ち、これを「モデルの数学的構造（R適合式の展開項、ブラケット記法、構造化された独立性情報）」に対する正本とする。この `generators` から実際の適合式（R formula）と数学的メタデータを演繹的に導出し、`switch` 文や独立した説明辞書との二重管理を廃止する。
- 独立性仮定は自然言語文章になる前に構造化する（`kind`: `mutual_independence`, `joint_independence`, `conditional_independence`, `none_implied`、および `statements`: `left`/`right`/`given`）。日本語の仮定文は、この構造化された独立性情報と `models.factor_map`（変数名・ラベル）から合成し、適合結果と評価基準から導く「結果の相対解釈」とは生成経路を明確に分離する。
- 結果 JSON においては、「変数対応（`models.factor_map`）」「数理的定義（`models.definitions`）」「数値比較表（`models.summary`）」を分離して保持する。`fitted_formula` には実際に適合へ渡した R の formula から取得した式を記録し、展開後の項の一致を検証する。`formula_latex` はブラケット記法と区別し、数式中の添字・期待度数・識別制約も説明する。
- $[AB][C]$ は生成クラス、$(A,B)\perp C$ は独立性として使い分け、`[AB]|[C]` を独立性表記に用いない。ブラケットは最大の交互作用項とその下位項を指定する記法であり、含まれる連関が非ゼロと実証されたことは意味しない。
- M1〜M9の対応を次のとおり固定する。M8・M9に条件付き独立を無理に割り当てず、「一般には独立性制約なし」と交互作用の制約を区別して記録する。

| ID | 生成クラス | 仮定・制約 |
| --- | --- | --- |
| M1 | $[A][B][C]$ | 3因子の相互独立 |
| M2 | $[AB][C]$ | $(A,B)\perp C$ |
| M3 | $[AC][B]$ | $(A,C)\perp B$ |
| M4 | $[BC][A]$ | $(B,C)\perp A$ |
| M5 | $[AB][AC]$ | $B\perp C\mid A$ |
| M6 | $[AB][BC]$ | $A\perp C\mid B$ |
| M7 | $[AC][BC]$ | $A\perp B\mid C$ |
| M8 | $[AB][AC][BC]$ | 全2因子交互作用を含み、3因子交互作用を含まない |
| M9 | $[ABC]$ | 飽和モデル。3因子交互作用まで含む |

### 互換性と表示・解釈の境界

- 数式メタデータのない旧JSONも描画可能とする。旧JSONの変数凡例は `input_summary.variables` の順序から明示的に導出してよいが、モデル定義の推測補完とは明確に区別し、未保存の数理定義は推測補完せず「数学的定義未収録」と表示する。有効な数理定義が存在する場合のみ主要指標カード等に構造仮定を表示し、定義未収録または内部不整合（変数対応・実適合式・モデル参照の矛盾）がある場合はその状態を表示して仮定の推測表示を保留する。
- 同じエンジンが扱う2元表にも、対応する2記号と既存モデル（M1: $[A][B]$、M2: $[AB]$）の定義を適用する。`model_key`（例: `3way_M2` vs `2way_M2`）により次元を明示管理し、3元表のM2の説明を流用しない。
- `models.summary` は現行の列構成（`model_id`, `model_name`, `df_residual`, `deviance`, `bic`）を維持し、既存の互換用 `model_selection.summary` との整合を保つ。ダッシュボードでは列を明示選択し、追加メタデータの全列表示による肥大化を防ぐ。
- モデル定義の存在と適合結果の成否を分離して扱い、詳細欄では「定義・結果の両方あり」「定義あり・結果未収録（理由は推測しない）」「旧JSON（定義未収録・数値比較は表示）」「2元表固有候補（3元表定義流用なし）」の各状態を保存情報の有無に忠実に表示する。今回の実装範囲は「保存済み状態の正しい表示」に限定し、統計エンジン（`pass1_compute.R`）内部で未保存のエラー（`tryCatch` での `NULL` 落ち等）に対する失敗理由の生成や評価候補の除外処理は別の実装範囲とする。記録済み失敗の表示検証には状態と理由を持つ検証用フィクスチャJSONを用い、この表示検証を統計エンジンの失敗処理全体の達成証拠とは扱わない。
- 完全な数式・日本語定義はDTセル内ではなく表直下の静的HTML（`<details>`）に配置し、DT再描画への数式組版依存を低減する。初回表示、詳細展開、狭い画面での改行、MathJax読み込み失敗時のフォールバック表示を実ブラウザでの検証対象とする。
- 表内の「数式・定義を見る」アンカーリンクから対応する `<details>` を展開し、見出しへフォーカス移動してキーボード操作を継続できるアクセシビリティを確保する（スムーススクロールは必須要件としない）。
- `jsonlite::toJSON(..., auto_unbox = TRUE)` における単一要素配列の型崩れ（スカラー化）を防止する入出力契約を担保する。
- BICとΔBICの定義・比較方向を提示し、最小BICは候補集合内の相対評価であることを明記する。モデルの絶対的適合、因果、差別の不存在の証明と同一視しない。最良モデルと局所セル診断の基準モデルも区別する。

## 受け入れ基準

1. UCB設定 `vars = [Dept, Gender, Admit]` で、`A = Dept`、`B = Gender`、`C = Admit` とM5の $[AB][AC]$ が一致する。学科の水準名A〜Fと因子記号の違いを明記する。
2. 3元表の全9モデルについて、適合式の項・生成クラス・独立性・説明が一致する。変数順序を入れ替えた場合も実変数の対応を追跡でき、2元表では不要なCや誤ったM2定義を出さない。
3. 同一入力・設定における数値検証を比較元ごとに分離して行い、(1) 既存JSONと比較してBIC・逸脱度・自由度・保存済みセル診断値が完全一致または許容誤差内で一致すること、(2) 変更前エンジンを固定した参照実行と比較して対数尤度・未保存適合情報が一致すること、(3) 独立したモデル対応表と比較して生成クラス・独立性が一致すること、(4) 実適合式を展開した項と生成クラスが一致することを確認する。最良モデルの初期展開は有効な `best_model_id` に従い、欠落・不正参照時にM1等を勝手に選択せず、同点候補の有無で挙動を揺らさない。
4. 新旧JSONで描画でき、凡例が主要指標カードより前に現れる。比較表（6列）と表直下のモデル詳細（`<details>`、最良モデル初期展開）が正常に機能し、数式・日本語名・表の可読性、表から詳細見出しへのリンク移動とキーボード操作継続が生成HTMLで確認できる。
5. Pass 2の記述例と品質確認項目に、仮定・相対評価・判断不能事項の区別を反映する。モデルIDだけを頼りに意味を推測せず、既存の `data_analysis_scope.md` に見られるM7/M5の取り違えを検出対象とする。
