## Context

現行のcanonical経路は、`vcd-categorical-analysis` を厳密な2次元エンジン、`vcd-bayesian-evidence-analysis` を3次元正本として分離している。前者の実行入口は `templates/analysis.R` と `templates/dashboard.Rmd` であり、`templates/report.Rmd` はレガシー資産である。一方、レガシーテンプレートには3次元モザイク図の分岐が残っているため、入口・責務・可視化の関係を文書とテストで明示する。現行の主可視化は、モザイク図ではなく、調整標準化残差、estimand、不確実性、および層別構造へ寄せる。

## Goals / Non-Goals

**Goals:**

- 2次元専用経路、3次元正本経路、レガシー資産の境界を同じ用語で表現する。
- 2次元ではHaberman型の調整標準化残差を主診断表示とし、期待度数、レバレッジ、Quarantine状態を同時に確認できるようにする。
- 3次元ではFacet残差マトリクス、条件付き割合ドット・区間図、サブグループ効果量Forest plotを優先する設計意図を明文化する。
- 残差は統計的乖離、RD/OR等は効果量、区間は不確実性という役割分担を明示する。
- レガシー `report.Rmd` を直ちに削除せず、誤ったcanonical入口として扱われないようにする。

**Non-Goals:**

- `vcd-categorical-analysis` の3次元対応。
- M1〜M9、BIC、三次元セル診断、条件付き割合計算の再実装。
- 統計計算、結果JSON、入力スキーマ、外部依存関係の変更。
- 既存レガシー成果物の一括再生成または削除。

## Decisions

### 1. 3次元対応は既存スキルへ統合せず、委譲契約を強化する

2次元の独立性・残差・Cramér's Vと、3次元の階層対数線形モデル・条件付き独立性を同一スキルへ統合すると、モデルと推定量の意味が混同される。したがって、既存の責務分担を維持し、入力境界と導線を仕様化する。

代替案として3次元入力を2次元周辺表へ自動縮約する方法は、条件付き構造と三次元交互作用を失うため採用しない。

### 2. レガシー資産は削除せず、非正本として固定する

直ちに `report.Rmd` を削除すると、過去成果物の再現や履歴参照を壊す可能性がある。ファイル自体は保持し、現行入口ではないこと、3次元正本ではないことを明示し、将来削除する場合の前提情報を残す。

### 3. 3次元の主可視化は層別残差とestimand表示とする

周辺association plotは第三因子による関係の変化を隠す可能性があるため、3次元DashboardではFacet残差マトリクス、条件付き割合ドット・区間図、サブグループ効果量Forest plotを主表示候補とする。モザイク図は現行の主表示・必須成果物から外し、必要な場合も非canonicalな探索補助に限定する。

### 4. 調整標準化残差を主診断量とする

2次元の主診断量は、行・列周辺の推定影響を調整したHaberman型の調整標準化残差とする。一般形は次で表す。

```text
r_adj[i,j] = (O[i,j] - E[i,j]) /
  sqrt(E[i,j] * (1 - p[i,]) * (1 - p[,j]))
```

この量は独立モデルからの統計的乖離を探索する指標であり、効果量ではない。小期待度数、ゼロ観測、高レバレッジ、多重性の影響を品質状態へ伝播し、閾値超過だけで自動判定しない。

### 5. 可視化の解釈を統計結果から分離する

残差図はモデルからの乖離、条件付き割合図は条件付きestimand、Forest plotは効果量と区間、Facet表示は層別構造の探索に使う。図の形状や色だけから有意性、実務的重要性、因果性、交互作用の確定、再現性を判定しない。

## Risks / Trade-offs

- [レガシー注記だけでは誤利用が残る] → 現行README、Skill説明、エラーメッセージ、テンプレート冒頭、導線テストで同じ境界を検査する。
- [3次元可視化を追加すると表示過密になる] → セル数・水準数の閾値、Top-Nまたは全件表へのフォールバック、図が答える問いの明示を既存Dashboard契約に従わせる。
- [残差と効果量が混同される] → 残差、RD/OR、条件付き割合、区間のestimandと解釈を図ごとに明記し、同じ色や閾値を異なる意味へ流用しない。
- [層別残差から交互作用を断定する] → 交互作用はM1〜M9等のモデル比較、逸脱度、BIC、効果量、および安定性で別途評価する。
- [レガシー資産の扱いが将来再び曖昧になる] → `report.Rmd` の非正本状態と削除判断条件をリファレンスへ記録する。

## Migration Plan

1. 仕様・責務リファレンス・Skill説明の用語をcanonical経路に合わせる。
2. レガシー `report.Rmd` に非正本・2次元専用・3次元委譲の注記を追加する。
3. 2次元Dashboardの調整標準化残差表示と、3次元DashboardのFacet残差・estimand表示要件を確認する。
4. 既存2次元・3次元テストを実行し、統計計算と既存成果物の不変性を確認する。
5. 問題があれば変更対象を限定して戻し、レガシー資産を削除せずに導線だけを復旧する。
