## MODIFIED Requirements

### Requirement: 問いとモデルの対応
モデル評価は、相互独立・条件付き独立・均一連関・3次交互作用を区別し、各候補の仮定、比較対象、評価する関連、生成クラス（`generators` を正本とするブラケット表記 $[AB][AC]$）、および因子記号と実変数の対応関係（`models.factor_map`）を明示しなければならない（MUST）。目的変数なしの探索と目的変数を指定する探索を支援し、関連を因果と断定しない。

#### Scenario: 因子記号と実変数を対応づける
- **WHEN** 分析変数 `vars` が指定される
- **THEN** 変数順序から導出した因子記号（$A, B, C$）と実変数名の対応表を保持し、学科名などの水準名と因子記号の混同を防ぐ注記を提供する

#### Scenario: 変数順序を変更しても対応が追従する
- **WHEN** 分析変数 `vars` の指定順序を変更する
- **THEN** 新たな順序に基づき $A, B, C$ と実変数の対応が再導出され、`response_var` の指定有無によって順序が暗黙に変更されず、実変数に基づくモデル説明が一貫して追従する

#### Scenario: 生成クラスから適合式と数理メタデータを導出する
- **WHEN** 3元表の候補モデルを評価・提示する
- **THEN** 生成クラス（`generators`）から展開した項の集合と、実際に適合へ渡した R 適合式の項の集合が完全に一致し、ブラケット表記、実変数展開表記、構造化された条件付き独立情報（$B \perp\!\!\!\perp C \mid A$ 等）が一貫して導出される

#### Scenario: 2元表で3元表の定義を流用しない
- **WHEN** 2元表を解析する
- **THEN** M2 を飽和モデル $[AB]$ として扱い、3元表の M2（結合独立 $[AB][C]$）の定義や不要な第3因子記号 $C$ を混入させない

#### Scenario: 均一連関と飽和モデルの制約を区別する
- **WHEN** M8（均一連関）および M9（飽和）を評価する
- **THEN** M8・M9 に条件付き独立性を無理に割り当てず、M8 は「全2因子交互作用を含み3因子交互作用を含まない」、M9 は「3因子交互作用まで含む」として交互作用の制約を区別して記録する

#### Scenario: 目的変数を指定しない
- **WHEN** 3変数だけを指定する
- **THEN** 特定の変数を自動的に結果変数とせず、各比較が問う関連と層別の意味を対等な探索として示す

#### Scenario: 目的変数を指定する
- **WHEN** 3変数の1つを目的変数に指定する
- **THEN** その条件付き割合や層別差に結び付けて説明し、他の2変数間の関連と区別する

#### Scenario: 均一連関と3次交互作用を比較する
- **WHEN** 全2因子交互作用までのモデルと3次交互作用を含むモデルを比較する
- **THEN** 2変数間の関連が第3変数の層によって変化するかを問う比較として示し、単なる全体の関連有無と区別する

### Requirement: 比較指標と評価状態の明示
モデル比較は、モデル識別子、尤度と標本単位、標本サイズ・パラメータ数・罰則の定義、比較の向き、推定と近似の区別、評価状態を記録しなければならない（MUST）。数値比較表（`models.summary`）と詳細な数理辞書（`models.definitions`）を分離して管理し、比較不能・識別不能・収束不良・近似条件不成立は理由付きで保留し、通常の順位付けに混ぜない。

#### Scenario: 定義と適合結果の双方が存在する
- **WHEN** 候補モデルの数理定義と適合結果の双方が記録されている
- **THEN** モデル定義、実際の適合式、および適合数値（自由度、逸脱度、BIC等）を表示する

#### Scenario: 定義はあるが適合結果が未収録である
- **WHEN** 候補モデルの数理定義は存在するが適合結果や失敗理由が記録されていない
- **THEN** 数理定義は提示可能とし、数値・判定欄には「適合結果未収録」と表示し、保存情報から適合失敗の有無や原因を推測しない

#### Scenario: 候補の適合失敗状態と理由が記録されている
- **WHEN** 候補モデルが識別不能・収束不良・近似条件不成立として評価失敗状態と理由が記録されている（検証用フィクスチャ等による入力を含む）
- **THEN** 保存された状態と理由を提示し、適合結果未収録と区別して表示する。未保存の失敗理由の生成やエンジン内部の候補除外処理自体の改修は別の実装範囲とし、この表示検証をエンジン失敗処理全体の達成証拠とは扱わない

#### Scenario: 旧JSON等で数値はあるが数理定義がない
- **WHEN** 記録データに数値比較結果は存在するが数理定義（`models.definitions`）が未収録である
- **THEN** 既存の数値比較結果を表示し、未保存の数式や生成クラスを推測して補完せず「数学的定義未収録」と明記する

#### Scenario: 既存数値とJSON構造契約を保持する
- **WHEN** 同一入力・設定で分析を実行し結果を保存する
- **THEN** 既存サマリー列と互換フィールドを保持し、自由度は完全一致、BIC・逸脱度・対数尤度・局所診断値は許容誤差内で一致し、単一要素配列等のJSON型契約を損なわない

#### Scenario: BICとEBICを併記する
- **WHEN** 同じ入力に両指標を提示する
- **THEN** それぞれの標本サイズと罰則を明示し、差があれば根拠を説明する。未確認のまま同等なベイズ因子と扱わない

#### Scenario: 候補の評価に失敗する
- **WHEN** 候補が識別不能・収束不良・近似条件不成立となる
- **THEN** 値の欠如と理由を示し、評価不能な候補の存在を隠して最良モデルを断定しない

## ADDED Requirements

### Requirement: モデル評価の視覚的提示とアクセス性
レポートおよびダッシュボードは、読者がモデルの前提と数理構造を誤解なく追跡できるよう、因子凡例、モデル比較、および数理詳細を階層的に提示し、操作性とフォールバック性を保証しなければならない（MUST）。

#### Scenario: 因子凡例を主要指標より前に提示し、有効な定義がある場合は構造仮定を明記する
- **WHEN** 分析レポートまたはダッシュボードを表示する
- **THEN** 因子記号と実変数の対応凡例を主要指標カードおよびAI考察より前に折りたたまず常時表示する。有効な数理定義が存在する場合は主要指標カード内でもBIC最小モデルの構造仮定を明記し、定義未収録または不整合の場合はその状態を表示して仮定を推測補完しない。旧JSONにおいて `factor_map` が未収録の場合は、`input_summary.variables` の順序から明示的に対応を導出して凡例を表示してよいが、モデル定義の推測補完とは区別する

#### Scenario: 比較表からモデル詳細へ移動しキーボード操作を継続できる
- **WHEN** 読者がモデル比較表から特定モデルの「数式・定義」リンクを操作する
- **THEN** 該当モデルの詳細領域（数理式・交互作用・独立性仮定）が展開・表示され、見出しへフォーカスが移動してキーボード操作が継続できる

#### Scenario: 有効な定義があり数式ライブラリ未読み込み時でも意味を理解できる
- **WHEN** 有効な数理定義が存在し、MathJax等の外部数式ライブラリの読み込みが遅延または失敗する
- **THEN** 等幅テキストによるブラケット表記（$[AB][AC]$）および日本語の構造解説テキストにより、数式描画なしでも各モデルの仮定が読者に理解できる

#### Scenario: 定義と実適合式やモデル参照に不整合がある
- **WHEN** モデル定義と変数対応・実適合式・モデル参照（`best_model_id` 等）の間に不整合が存在する
- **THEN** 該当モデルの数学的説明を保留して不整合状態を明示し、正常な定義や推測補完した説明と混同して表示しない

#### Scenario: 旧JSONでも視覚的レイアウトを維持する
- **WHEN** 数理定義を含まない旧JSONデータをダッシュボードで表示する
- **THEN** 画面がクラッシュすることなく既存の数値比較表を表示し、詳細領域には「数学的定義未収録」と表示して推測した数式を出さない
