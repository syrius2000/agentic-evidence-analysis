## 1. 目的と決定事項

`vcd-categorical-analysis` が生成する完全オフライン Scientific Dashboard に、ユーザー選定の「臨床・学術標準」テーマを導入する。これは特定の学術誌の外観を複製するものではなく、Nature Research Figure Guide の可読性・アクセシビリティ原則を、既存の統計的責務分離を壊さない範囲で適用する変更である。

確定する視覚言語は次のとおりとする。

| 視覚要素 | 固定する意味 |
| :--- | :--- |
| 色相 | 常に行変数 `A` のカテゴリ（例: Placebo / Treat）。Section 7.2 を含めて切り替えない。 |
| 点形状・線種 | 事後中央値／平均、通常セル／Dual-Filter候補等の表示役割。 |
| 琥珀色の太枠・中空記号・明示注記 | `QUARANTINED`。隔離が第三の群であるかのように表示しない。 |
| 発散色 | Section 4 の残差の正負だけに使用し、行群色へ置換しない。 |
| 中立グレー | 基準線、グリッド以外の補助線、非主表示の補助要約。 |

## 2. 根拠とデザイン制約

Nature Research Figure Guide に基づき、以下を受入条件へ採用する。

- 色覚多様性に配慮したパレットを使用し、凡例では色付き文字ではなく色見本と黒系のテキストを用いる。
- 軸線・目盛り・単位を維持し、可読なサンセリフ体を使用する。
- 背景グリッド、装飾的アイコン、ドロップシャドウ、パターン、過密なラベルを追加しない。
- 完全オフライン契約を維持し、外部フォント、CDN、外部CSS/JS、外部画像を追加しない。

画面用のRGB配色は次を基準にする。行カテゴリが2水準の場合の順序は、結果JSONに出現する行水準の決定論的順序に従う。3水準以上の水準数に対する安全な拡張パレットと、水準数が拡張パレットを超える場合のフォールバック規則を実装前に明文化する。

| 用途 | 色 |
| :--- | :--- |
| 背景／カード | `#FFFFFF` ／ `#F6F8FB` |
| 本文／補助文字 | `#152238` ／ `#64748B` |
| 行群第1色／第2色 | `#1F4D7A`（ネイビー）／`#9B2945`（バーガンディ） |
| Section 4 正／負残差 | `#0F766E`（青緑）／`#B45309`（黄褐） |
| Dual-Filter候補 | `#6D28D9`（紫、候補形状と併用） |
| 隔離セル外枠・注記 | `#A16207`（琥珀） |

## 4. 実装手順

1. 作業開始時のGit差分と対象テストの基線を確認する。ユーザーの既存差分・未追跡ファイルを保存する。
2. `dashboard.Rmd` 冒頭に、背景、本文、補助文字、基準線、状態色を一元化したテーマトークンを置く。テーマ固有の色値を各図へ散在させない。
3. 行水準から決定論的に色を返すヘルパーを追加する。Section 6の現在の動的`Dark2`も同ヘルパーへ統合し、Section 3、7.1、7.2、8、9、10で同じ行カテゴリを同じ色相にする。
4. Section 3は、色相を行群、形状を通常／候補、琥珀色の外枠または中空記号を隔離に割り当てる。既存の候補抽出条件は変更しない。
5. Section 4は、棒の`fill`を残差の正負・候補・隔離という状態表現に維持する。行群はラベル横の小さな色見本等の二次符号とし、残差方向と群を混同させない。
6. Sections 7.1、7.2、9は、信用区間と主表示の中央値を行群色で示し、平均は形状と中立グレーで区別する。Section 7.2の列カテゴリ`B`は条件見出し・セルラベルで示し、色相には用いない。
7. Sections 8、10は棒の行群色を使う。Section 9は区間・中央値を行群色に使う。全ての隔離表示はパターンを使わず、太枠・中空記号・注記で統一する。
8. Section 11の後へSection 12を追加する。初期状態を閉じたネイティブHTMLの`details`／`summary`を使い、以下を日本語本文で提示する。
   - 全体連関・効果量
   - 局所セル診断と4軸
   - ベイズ事後推論と不確実性
   - 学術リファレンス
9. 用語は正本リファレンスと一致させる。Bergsmaは「有限標本バイアス低減」、`log(O/E)`は「独立モデル期待度数に対する局所的乗法乖離」、Raoスコアは「統計的証拠強度」とする。「保証」「統計的確信度」「不偏推定量」等の過剰表現は使わない。調整残差の文献にHaberman (1973)を含める。
10. 一時出力でレンダリングし、静的検査、対象Rテスト、外部参照・絶対パスのスキャン、ブラウザによる目視確認を行う。現行runの統計値と新しいテーマ出力の統計値が一致することを確認する。

## 5. 検証と受入条件

| 区分 | 受入条件 |
| :--- | :--- |
| 静的 | `dashboard.Rmd` が外部URL・CDN・外部フォントを追加せず、Section 12と4個の`details`を含む。 |
| 視覚契約 | Section 7.2を含め、同一行水準が同一色相である。Section 4の棒塗りは残差状態を保つ。隔離は色だけに依存しない。 |
| 統計契約 | 数値、順位、候補、隔離、事後要約、JSONはテーマ変更前後で不変。 |
| レンダリング | 小規模・中規模・大規模表の分岐を含む既存ダッシュボードテストが成功する。 |
| オフライン | 出力HTMLの静的スキャンで外部通信、CDN、OS絶対パスを検出しない。 |
| 目視 | デスクトップ幅で軸・凡例・日本語ラベルが重ならず、Section 12が開閉可能である。 |
