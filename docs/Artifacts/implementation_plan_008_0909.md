# Pass 0 コンサルテーション必須化の実装計画

created: 2026-09-09 09:25 (JST)
update: 2026-09-09 16:24 (JST)
author: Codex (GPT-6 / GPT-5)

## 背景

`vcd-pass0-consultation` は本リポジトリの分析鉄則である一方、Bayesian、Categorical、Questionnaire の各スキルには「推奨」「任意」「設定がある場合」という記述が残り、Pass 1 の公開エントリーポイントも設定なしの直接実行を許している。そのため、AI エージェントまたは利用者が、入力構造、分母、欠測、層別、複数回答、過剰次元を確認しないまま統計計算へ進める。

一方で、Pass 0 の実行有無を単純な真偽値だけで判定しても、相談とデータ検分の品質は保証できない。`examples/OTC_Q02a.csv` の試行では、2段ヘッダーにより症状名がデータ行、度数値が文字列カテゴリとして認識された。したがって、Pass 0 の必須化は、検分品質、設定の由来、テスト移行を整えたうえで段階的に実施する。

## 設計判断

- AI が新規分析を開始するときは、`vcd-pass0-consultation` を最初の必須ステップとする。
- 利用者向けの Pass 1 公開エントリーポイントでは、有効な `analysis_config.json` を必須とする。
- `pass0_completed: true` のような自己申告の真偽値だけでは、Pass 0 完了と判定しない。
- `--allow-raw-cli` のような通常利用可能な迂回オプションは追加しない。
- 単体テストは内部計算関数を直接検証できる。公開 CLI の統合テストは Pass 0 設定フィクスチャを使用する。
- 既存 legacy run は書き換えず、既存成果物の参照・preview 契約を維持する。

## 目的

新規カテゴリカル分析において、Pass 0 の検分・対話・設定確定を Pass 1 の前提とし、分析設計と統計計算の間に検証可能な引き継ぎを作る。同時に、既存の統計計算、モデル式、閾値、乱数、出力数値および run ライフサイクルを維持する。

## 対象範囲

### 1. Pass 0 検分品質

- `.agents/shared/inspect_data.R` が、通常の1段ヘッダーCSVを正しく検分できることを維持する。
- 2段ヘッダー、空列名、数値列への文字列混入など、度数列とカテゴリ変数を安全に決定できない入力を検知する。
- 自動判断できない入力では、誤った `analysis_config.json` を生成せず、整形または利用者確認が必要であることを明示する。
- Pass 0 の検分出力先を正式 run と区別できる作業領域に統一し、`run_<id>` を使う例と「正式 run 非作成」の記述矛盾を解消する。

### 2. Pass 0 成果物と由来契約

Pass 0 の合意後に、作業領域へ次の成果物を生成する。

- `inspection_results.json`: 入力構造、型、水準、欠測、度数候補および入力SHA-256を記録する。
- `data_analysis_scope.md`: 分析目的、変数選択、分母、除外、集約、層別、複数回答、解釈保留を日本語で記録する。
- `analysis_config.json`: Pass 1 が読み取る単一正本設定と由来情報を記録する。

`analysis_config.json` には単純な完了フラグではなく、少なくとも次の `pass0_provenance` を持たせる。正確なキー名と型は、実装前に共通スキーマで固定する。

- Pass 0 契約バージョン
- `inspection_results.json` のリポジトリ相対パス
- `inspection_results.json` のSHA-256
- 検分対象入力のSHA-256
- 設定確定日時（JST）
- 対象スキル

Pass 1 は、設定ファイルの構造、対象スキル、入力ファイルの実SHA-256、検分時SHA-256、および検分成果物の実SHA-256を計算開始前に照合する。外部入力を使用する場合は、既存の `hash_only` 方針を維持し、元データを無断でコピーしない。

### 3. スキル別のPass 0契約

- Bayesian: 2-wayまたは3-wayの `vars`、`freq`、任意の `response_var`、モデル選択前提を確定する。
- Categorical: `vcd-pass0-consultation` と必要に応じた `analysis.R --profile` を組み合わせ、次元、水準、描画対象、集約方針を確定する。
- Questionnaire: 共通の入力検分に加え、`question_config.csv`、設問種別、分母、欠測、複数回答、層別、補正方針を確定する。Bayesian 用設定をそのまま流用せず、共通項目とQuestionnaire固有項目を分ける。

3スキルの frontmatter と本文は、Pass 0 を「推奨」「任意」ではなく、新規分析における必須依存・順序厳守として統一する。

### 4. Pass 1 公開エントリーポイント

- Bayesian、Categorical、Questionnaire の利用者向け Pass 1 実行では `--config` を必須にする。
- 設定欠落、由来不一致、入力改変、変数不一致、対象スキル不一致は、正式 run の予約および統計成果物の作成前に非ゼロ終了する。
- ヘルプ表示、Pass 0 profile、設定検証だけの操作は、統計計算を開始しないため対象外とする。
- テストを通す目的の公開迂回フラグや、通常利用者が設定できるPass 0省略用環境変数は追加しない。

### 5. テスト移行

既存テストを一括削除または一括書換えせず、次の分類に基づいて移行する。

1. 公開CLI統合テスト: 有効なPass 0設定フィクスチャを渡し、実運用と同じ入口を検証する。
2. 統計単体テスト: `pass1_compute.R` などの内部計算関数を直接呼び、Pass 0ゲートと統計数値の検証を分離する。
3. 拒否テスト: `--config` 欠落、由来欠落、ハッシュ不一致、対象スキル不一致で、run非作成かつ非ゼロ終了を確認する。
4. legacyテスト: 現行契約との重複または廃止済みUIに依存するものは、保証内容と代替テストを記録して `tests/legacy_quarantine/` へ移す。削除は別途明示承認の対象とする。

数値不変性、統計基盤、run予約、排他ロック、原子的確定、改ざん検知、sealed、supersede、symlink防御、可搬パスのテストは維持する。

## 実装段階

### 段階1: Pass 0 基盤の整備

- `inspect_data.R` の入力構造検証と診断出力を改善する。
- Pass 0 作業領域の命名と保存契約を統一する。
- `pass0_provenance` の共通スキーマとハッシュ検証方法を確定する。
- 1段ヘッダー、2段ヘッダー、度数列不明、文字列混入のテストを追加する。

### 段階2: スキル文書とテストの移行

- 3スキルの依存関係、実行順序、エラーメッセージを統一する。
- 共通設定フィクスチャ生成ヘルパーを用意し、公開CLI統合テストを移行する。
- 内部関数の単体テストと公開CLIの契約テストを分離する。
- README、共通品質契約、各スキルの成果物表とコマンド例を同期する。

### 段階3: Pass 1 ゲートの有効化

- 3スキルの公開エントリーポイントで `--config` と由来照合を必須にする。
- FAIL-FAST が正式 run 作成前に機能することを確認する。
- 既存ライフサイクル、数値不変性、各スキルのスモークテストを再実行する。

段階1または段階2で契約変更が必要になった場合は、本計画を更新し、段階3へ進む前に再承認を得る。

## 非対象

- 統計手法、モデル式、閾値、乱数、Evidence Score、Cramér's V、BIC計算の変更
- 既存結果の一括再計算
- 既存 legacy run および封印済みrunの書き換え
- `tests/` の一括削除または大規模なディレクトリ再編
- commit、push、外部システムへの書き込み

## 受入条件

- 3スキルの `SKILL.md` が、新規分析では `vcd-pass0-consultation` を最初に使用することを明記する。
- 通常の1段ヘッダーCSVでは、入力型、水準、欠測、度数候補および入力SHA-256が正しく記録される。
- 安全に解釈できない2段ヘッダー等では、誤った設定を自動確定せず、診断理由が成果物と標準エラーに示される。
- `analysis_config.json` の由来情報と、実際の検分成果物・入力ファイルのハッシュが一致する。
- 公開Pass 1を `--config` なしで起動した場合、正式 run や統計成果物を作成せず非ゼロ終了する。
- 有効なPass 0設定を渡した場合、既存のPass 1出力契約が成立する。
- 設定不備、入力改変、検分成果物改変、対象スキル不一致は計算開始前に拒否される。
- Questionnaireの設問設定、分母、欠測および複数回答の確認結果が引き継がれる。
- 既存の数値不変性、統計基盤、ライフサイクル、セキュリティ、可搬性テストが通過する。
- 本番CLIにPass 0を省略する公開フラグが存在しない。

## 検証

- `inspect_data.R` の正常入力・2段ヘッダー・空列名・度数列不明・文字列混入テスト
- 3スキルそれぞれのPass 0なし拒否、正常設定成功、入力改変拒否、由来改変拒否テスト
- Questionnaire固有の設問設定・分母・複数回答引き継ぎテスト
- `tests/test_run_scope_lifecycle.R`
- `tests/test_run_scope_guards.R`
- `tests/test_relocatable_run_lifecycle.R`
- `tests/test_ucb_numerical_invariance.R`
- `tests/statistical_foundations/test_*.R`
- Python契約テスト
- `git diff --check`
- 新規JSON、Markdown、HTMLの個人絶対パス漏洩スキャン

## リスクと抑制策

- 既存CLI利用との互換性: 公開CLIの切替前にテストとコマンド例を移行し、エラーには必要なPass 0手順を表示する。
- 形式だけのPass 0: 真偽値ではなく、入力と検分成果物のハッシュ連鎖を検証する。
- 誤った自動推測: 判断不能な入力は停止し、利用者との相談へ戻す。
- テスト肥大化: 同じ保証を重複検証するテストは、保証対応表を作成して統合候補とする。削除は本計画に含めない。
- 3スキル間の過度な共通化: 共通由来契約とスキル固有設定を分離する。

## 承認境界

本計画の修正は計画作業であり、コード、テスト、スキル本文、README、設定スキーマの変更をまだ承認するものではない。実装は、本計画についてユーザーから明示的な「承認します」または「実行して」を受けた後に開始する。
